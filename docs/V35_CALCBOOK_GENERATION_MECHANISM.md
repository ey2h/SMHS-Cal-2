# V35 计算书生成原理（代码级）

> 取证对象：`local-data/recon/unpack/unpacked_runtime.exe`（V35 ASPack 脱壳镜像，ImageBase 0x400000）
> 本文只写**能在二进制里指到地址**的东西。凡未定位的，显式写「未定位」，不补推测。

## 一、主函数

| 项 | 值 |
|---|---|
| 入口 | `0x01B36238` |
| 特征 | `push ebp / mov ebp,esp / sub esp,0x18` + `mov eax,0xAA4; call 0x419AC0`（VB6 栈探测） |
| 局部变量 | 0xAA4 = **2,724 字节**（巨型函数，单函数覆盖约 0x1B36238–0x1B51xxx） |
| 性质 | **只做编排**：调子函数 + 刷进度条，正文不在这里拼 |

## 二、九个阶段（文案与其代码地址，按执行顺序）

`call dword ptr [eax+0x54]` 一律是给 Word `Application.StatusBar` 写进度文字，
所以这九句就是**生成流程的骨架**：

| # | 文案 | 地址 | 含义 |
|---|---|---|---|
| 0 | `正在运行，请稍候！` | `0x01B37DE3` | 入口提示 |
| 1 | `程序进行完整性检查……` | `0x01B3AE66` | 完整性检查 |
| 2 | `计算书文本生成……` | `0x01B3B407` | **正文文本产出** |
| 3 | `计算书字体、间距调整……` | `0x01B3CF95` | 字体/行距 |
| 4 | `设计计算书    ` | `0x01B4220A` | 封面标题（注意尾部 4 个空格，是模板对齐留下的） |
| 5 | `计算书封面、目录生成……` | `0x01B42B07` | 封面 + 目录 |
| 6 | `计算书格式化一级标题……` | `0x01B44E5C` | H1 |
| 7 | `计算书格式化二级标题……` | `0x01B45965` | H2 |
| 8 | `计算书格式化三级标题……` | `0x01B4631E` | H3 |
| 9 | `计算书其它处理……` | `0x01B47089` | 收尾 |

另有 `生成计算书`（`0x004E22F8`）在 `0x01B391D5 / 0x01B3973C / 0x01B39C91 / 0x01B3A8A1`
被 push 四次 —— 用于**四种主类型分支各自的进度标题**。

### 关键结论：标题不是数据结构，是「后处理」
第 2 步先把整本正文当**纯文本**生成，第 6/7/8 步再回头扫文本里的 `§N.` 锚点，
把匹配到的段落套上「标题 1 / 2 / 3」样式。

这解释了为什么 V35 里搜不到成体系的章节名数组：
章节名散落在一段段正文文本里，由 `§` + 变量章号 + `.` + 标题 拼成，
**章号随幕墙类型变**（同一章在不同类型下编号不同，见第四节）。

## 四、规范清单：8 个文件 + 按类型选一个

`.\规范\规范1.txt` ~ `规范8.txt` 在字符串池 `0x4D8740` 起，
代码在 `0x0A5850E`（`.\规范\` 前缀）与 `0x0A58513 / 0x0A5871E / 0x0A58929 / 0x0A58B34 /
0x0A58F1E / 0x0A59129`（六处，各自 push 一个 `规范N.txt`）被引用 ——
形态是 VB6 的 **VARIANT 数组字面量构造**（`push 0x4D8750; call 0x419D2A` →
`mov [ebp-0xD8],0x4008` → `push 0x10; call 0x419AC0` → 4×`movsd`）。

判定点：`0x1AA43B6`、`0x1AA4BDC` 两处（相隔 0x826，是一对并列分支）
通过 `call dword ptr [eax+0x524]` / `[eax+0xE0]` 读某个 COM 属性（疑似下拉框 ListIndex），
再按索引取数组里的规范文件。

### 八个文件全部被引用（8 分支 × 2 组）

全段扫描（range 0x4D8000–0x4D9000，push/lea/mov/cmp 四类立即数）：

| 文件 | 字符串 VA | 引用点 |
|---|---|---|
| 规范1.txt | `0x4D8750` | `0x0A58513`、`0x1AA43B6`、`0x1AA4BDC` |
| 规范2.txt | `0x4D8788` | `0x0A5871E`、`0x1AA4488`、`0x1AA4CF8` |
| 规范3.txt | `0x4D87C8` | `0x0A58929`、`0x1AA455A`、`0x1AA4E14` |
| 规范4.txt | `0x4D87F4` | `0x0A58B34`、`0x1AA462C`、`0x1AA4F30` |
| 规范5.txt | `0x4D88C8` | `0x0A58F1E`、`0x1AA46FE`、`0x1AA504C` |
| 规范6.txt | `0x4D8A54` | `0x0A5947A`、`0x1AA47D0`、`0x1AA5168` |
| 规范7.txt | `0x4D88F4` | `0x0A59129`、`0x1AA48A2`、`0x1AA5284` |
| 规范8.txt | `0x4D8A98` | `0x0A596A2`、`0x1AA4974`、`0x1AA53A0` |

`0x1AA43B6`~`0x1AA4974` 与 `0x1AA4BDC`~`0x1AA53A0` 是**两组各 8 分支的选择链**
（组内按 1→8 顺序排列，两组相距 0x826）——即代码里明确是「8 种情况 → 8 个文件」。
`0x0A58xxx` 那一组是数组/VARIANT 构造，注意它内部顺序是 1,2,3,4,5,**7,6**,8。

> 复盘教训：第一次扫只取了 `0x4D8000–0x4D8A00`，而 `规范6.txt`（0x4D8A54）与
> `规范8.txt`（0x4D8A98）正好在边界外，一度误判成「节能/隔声不读清单文件」。
> 用样本核对才发现：节能样本第 1 章正好 **19 条**，与 `规范6.txt` 的 19 行逐条对应
> （首条同为《建筑节能与可再生能源利用通用规范》GB55015-2021）。
> **扫描范围不能拍脑袋定，边界必须用样本反查确认。**

## 五、`jss\模板.doc` 的真实角色

两处引用：`0x0A5766A` / `0x20A81AD`（VA `0x4D82D0`）与 `0x0A5808C` / `0x0CF450E`（VA `0x4D8460`）。

`模板.doc` 的 `WordDocument` 流只有 4,721 字节、18 段纯文本：

```
工程名称 / 设计计算书 / （十余个空段） / 设计： 校对： 审核： 批准： / 目录 / indexindex
```

**但这不等于封面上只有这些行。** 程序真实产出（`计算书样本文件集/节能计算书.DOC`）的封面是：

```
北京xx幕墙装饰工程          ← 工程名称
外装饰结构热工性能          ← 副标题（幕墙类型／计算主题）
设计计算书
（空行）
设计：／校对：／审核：／批准：
沈阳yy铝业工程有限公司      ← 单位
二〇二五年三月二十四日      ← 中文数字日期
目录
```

⇒ 单位与日期是程序**在四签之后动态插入**的，模板文件里看不到。
**教训：模板文件的静态文本不能当作最终版面，必须用样本（程序真实输出）核对。**
（本复盘曾据模板文件删掉「副标题/单位/日期」三行，是错的，已回退。）

## 六、`.CAC` 章节模板：文件名可得，正文不可得

V35 代码里引用 `.\jss\A001.CAC` ~ `A451.CAC`（大小写混排，去重后 400+ 个）。
`0x000D8694` 起是一片并列的字符串块：`.\规范\` + `规范1.txt` + `A140.CAC` + `规范2.txt` +
`金属板雨篷` + `A143.CAC` + `规范3.txt` + …

**但安装目录 `jss\` 下只有 `.CAM`（CSV 型材数据），没有 `.CAC` 正文文件。**
`jss\jss.dat` 是 emx 0.9d 的 OS/2 可执行（`MZ` + `LX` 头），与本软件无关。

已定位的三组「同章不同号」证据（都在字符串池，UTF-16 明文）：

| 章标题 | 章号 | 配套 CAC |
|---|---|---|
| 耐候胶胶缝计算 | `§35.` | `A113.CAC` + `A116.CAC` |
| 耐候胶胶缝计算 | `§36.` | `A366.CAC` + `A367.CAC` |
| 耐候胶胶缝计算 | `§32.` | `A115.CAC` + `A118.CAC` + `A120.CAC` |

地址：`0x4E23FC`（§35）、`0x4E24A8`（§36）、`0x4E2530`（§32）。

⇒ 与用户说的「全隐框、明框、铝板、石材模板框架可能不一样」相符；
但**正文内容无法从文件取得**，这条登记为未定位。

## 七、复刻版的对应实现

| V35 做的事 | 复刻版 | 是否等价 |
|---|---|---|
| 第 2 步「文本生成」拼纯文本 | `CalcBookComposer.Compose` 产出 `BookBlock` 流 | 等价 |
| 第 6/7/8 步用 `§N.` 锚点套标题样式 | 直接产出 H1/H2/H3 + `w:outlineLvl` 0/1/2 | 等价（结果一致，免去后处理） |
| 第 5 步封面/目录 | 封面 + `w:fldSimple TOC` 域 | 等价（目录用域，Word 里 F9 更新） |
| 规范清单取 `.txt` | `BookSpecSets` 逐字副本 + 按类型选套 | 等价 |
| Word OLE 自动化 | 直接写 OOXML | **有意不同**：不依赖本机 Office/WPS |
