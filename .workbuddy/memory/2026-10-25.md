## 手册依据（用户提醒：分配有原则，别凑数字）

**教训**：我在 t_e 上连续尝试拟合系数（0.95³、0.95005、加常数项），方向错了。

### 手册原文（`docs/recon/help/plain/B01.txt`「10 板块配置」）
- `515` 中空+夹层：两片玻璃**先夹胶后**再与另一片玻璃组成中空玻璃
- `518` 三玻双中空：**三片玻璃**组成的具有 **2 个中空层**的结构
- `519` 双夹层中空：**四片玻璃**组成的中空层的结构

### 据此的原则（不是拟合）
```
先夹胶  t_l = (t1³+t2³)^(1/3)          夹层分支无 0.95（代码 0xA28B80 段）
再中空  t_e = 0.95·(t_l1³+t_l2³)^(1/3)
合并    t_e = 0.95·(Σt³)^(1/3)
```
本实现 `(Σ(0.95tᵢ)³)^(1/3)` 与之**数学恒等** ⇒ 完全遵守手册原则。

### 手册只给原则、不给数值
全手册 40+ 页 grep「等效厚度」「荷载分配」「各片」**零命中**；
`B04` 只到强度设计值表 + 加工说明；玻璃段 2 张图是节点构造图（不是公式）。
⇒ 0.95 这类系数只能以代码为准（`0xA28B80` 就是中空等效厚度函数）。

按每片穿越腔数累积才得实测 7.952：`[(0.95t₁)³+(0.95²t₂)³+(0.95²t₃)³]^(1/3)`。

## 界面验收 + 参数库改造（用户两条关键纠正）

### 教训一：不能只看弹窗就下结论
上一轮看到「欢迎进入软件注册！」就判定「其它玻璃计算不可用」——错。
`IsWindowVisible(0x7d026a)=1`、763×500、可预演。**要看窗体本身状态，不是看弹窗。**

### 教训二：新界面必须真的打开看，不能只跑单元测试
用户问「我都没看你开自研的界面，会不会和 UI 不匹配」，一截图发现三个真 bug：
1. **整个面板 DataContext 没接** —— `CalcMainWindow.Show()` 只做 `_host.Content = e.Create()`，
   其余 CWxx 是纯静态复刻（XAML 写死文本）不需要 DataContext，新面板需要。
   → 在 `CalcFormCatalog` 的 `Create` 里挂 VM。
2. **四个厚度下拉全空** —— `SelectedIndex="3"` 在 `ItemsSource` 到达前设置，
   列表空 → SelectedIndex 被重置为 -1。
   → 改用 `SelectedItem="{Binding T1}"`（与常规玻璃屏同一模式，那个一直是对的）。
3. αmax 标签换行 → NoWrap。

**截图方法**（可用）：`PrintWindow(hwnd, hdc, 2)` 抓窗口内容，不受遮挡影响；
用 `GetWindowDC + CreateCompatibleBitmap + GetDIBits` 转 PIL Image。
启动走 `--calc --menu=其他计算/其它玻璃计算`（项目自带诊断参数，走真实菜单路径）。

### 教训三：参数库的边界
用户要求「不要写死，必须调参数库」，随后澄清「玻璃厚度是常量」。核查后分工：
- **参数库确实没有玻璃材料表**：59 表全是型材/板材截面表；两处 `参数库.mdb` MD5 相同
  （6c59ee99...）；导出脚本用 `GetSchema("Tables")` 全量无过滤；全部 CSV 无「强度设计值」列。
- 所以：厚度档/种类档/胶片档 = V31 窗体程序常量（源码保留，注明）；
  密度/弹性模量/强度设计值 = 参数库读取。
- 落地：`local-data/hb_mdb/玻璃材料（复刻补充）.csv` + `ParamLibrary.Glass.cs`
  （沿用 `LoadColumns` 模式：读 CSV，读不到才用编译期快照）；
  `GlassAllowables` 只转发，`GlassEngine.DensityNmm3/E` 改引用参数库。
- 断言 `ParamLibrary.GlassTableLoaded == true` 确保真读了 CSV 而不是走快照。
