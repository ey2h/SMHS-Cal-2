### 3.1 混凝土 fc / ft：代码里就是 `If 等级 = "Cxx" Then 槽 = 字面量`

### 3.2 锚筋材质：两个输出同时定死 fy 与 α

| 材质 | 外型（联动） | lab | la | 锚筋总截面积计算值 |
|---|---|---|---|---|
| HPB300 | 光圆 sel=0 | 449.008 | 57.507 | 57.911 |
| HRB400 | 带肋 sel=1 | 436.535 | 50.319 | 52.188 |

- 截面积式 ∝ `1/fy` ⇒ 由 52.188 反解 **fy = 300**；
- 锚固式 `lab = 1.1·α·(fy/ft)·d` ⇒ `α·fy = 42.0` ⇒ **α = 0.14**。
两条独立方程互相印证，且 0.16/0.14 正是「光圆/带肋」的规范分档。

**已闭合（2026-10-26）**：HRB400 的 `la`，V31 = **50.319**，复刻现为 50.319（原 50.385 差 0.066）。
根因不是取整位数，而是**分子取错了分支**——见 3.3。

### 3.3 锚筋面积两条分支 + `la` 恒取分支2（HRB400 差异的真正根因）

代码里 asReq 算了**两条式子**（都在 `0x1923F00–0x1924B00`），且都不含"取较大值"的判断，
比较发生在后面的显示点。系数：

| 系数 | 算式 | HPB300 | HRB400 | 地址 |
|---|---|---|---|---|
| αr（层数影响） | 2 层 → 1.0 | 1 | 1 | `0x1924359` 的 `Div 1716/1` |
| αv（抗剪影响） | `round3((4−0.08d)·√(fc/fy))` | 0.638 | 0.605 | `0x1924378` |
| αb（锚板厚度） | `round3(0.6+0.25t/d)` | 0.767 | 0.767 | `0x19243DC` |

**分支1** `0x19244B7`：`V/(αr·αv·fy) + N/(0.8·αr·αb·fy) + M/(1.3·αr·αb·fy·z)`
**分支2** `0x1924A7D`：`N/(0.8·αr·αb·fy) + M/(0.4·αr·αb·fy·z)` ← **无剪力项**

| | HPB300 | HRB400 |
|---|---|---|
| 分支1 | 9.9617 + 42.8455 + 4.6357 = **57.443** | 9.4545 + 38.5610 + 4.1721 = **52.188** |
| 分支2 | 42.8455 + 15.0659 = **57.911** | 38.5610 + 13.5593 = **52.120** |
| 屏幕显示（max，`0x1925120`） | 57.911 | **52.188** |
| `la` 的分子（`0x1926B20`） | 57.911 | **52.120** ← 分支2 |

`la = lab × round3(分支2) / As实配`（`0x1926B20` Div → `0x1926B3F` Mul）：

- HPB300：`57.911/452.16 = 0.12807634` → `×449.008 = 57.5073` → **57.507**
- HRB400：`52.120/452.16 = 0.11526893` → `×436.535 = 50.31892` → **50.319**

两个坑：
1. 分子用 `max(分支1,分支2)` 只在 HPB300 侥幸对（两分支 57.911 恰为较大）；
2. 分子**必须先 round3**——用原始 `branch2 = 57.91141532…` 会算成 57.508。

> 依据：`v31runs/embed_hrb400_vartrace.json`（切锚筋材质到 HRB400 后完整预演，234 条 Variant 记录）。

## 八、焊缝几何：反汇编 + Variant 实值轨迹双证（不是按教科书重写）

### 8.1 调用性质：全部是 Variant，没有 x87

`0x1A64240–0x1A65000` 与 `0x1A6D700–0x1A6E000` 两段里**没有一条 x87 指令**，
所有算术都走 msvbvm60 的 Variant thunk（`v31_thunks.json` 解析名）：

| thunk | 名称 |
|---|---|
| `0x413714` | `__vbaVarMul` |
| `0x413708` | `__vbaVarDiv` |
| `0x413552` | `__vbaVarAdd` |
| `0x41377A` | `__vbaVarSub` |
| `0x41370E` | `__vbaVarPow` |
| `0x41371A` | `rtcRound` |

所以「按 x87 反编译推公式」在这两段是行不通的——必须同时读**地址序列**和**每个调用的操作数实值**。

### 8.4 材料表（fc/ft）：**已升级为代码级闭合**（并订正两处误判）

**结论**：fc/ft 全部由 `fld qword ptr [常量池]` 直接取，地址与等级一一对应（见第三节表）。
13 条 `If 等级="Cxx"` 分支各自把字面量写进临时槽 18（fc）/ 48（ft）。

**订正 1（错判槽数组）**：早前把 `0x1C911F4` 当成「材料专用槽数组」——**错**。
该地址被引用 **12470 次**，是 VB6 函数的通用 Variant 临时槽区；槽号（18 / 48）只是其中两个下标，
不能按它反查材料来源。

**订正 2（漏搜 ModRM）**：早前搜「代码是否引用常量地址」用了 `<DD><addr>`，漏了 `fld qword ptr [abs]`
的 ModRM 字节 `05`，于是得出「0 处引用」的错结论，进而误判为「只能靠输出反读」。
正确字节形态是 `DD 05 <addr32>`（例：`0x1922631` = `dd 05 88 b9 40 00`）。

**保留的旁证**：`fc`/`ft` 的常量池里连排布局仍可作为交叉检查——
`ft` 2.04/1.96/1.89/1.71/1.43/1.27 连排 `0x40B910–0x40B938`、
`fc` 35.9→11.9 连排 `0x40B940–0x40B988`；
`1.80/1.57/9.6/16.7/29.7` 被编译器去重到 `0x403330/0x40A360/0x4027E0/0x4049E8/0x4054C8`。

**测试锁定**：`EmbedMaterialLiteralTests`（27 条）逐级断言 13 级 fc/ft 字面量，
并强制表长 13、fc 严格单调（防止有人把 ft 缩回 9 项再靠 clamp 兜底）。
