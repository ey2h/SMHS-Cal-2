# 看数据真实传递，不看计算书

> 用户口径（2026-10-24）：**挖掘时不看计算书，要看数据真实的传递。**
> 本文把这句落成可执行的方法，并给出用该方法在 V35 立柱函数上跑出的第一批结果。

---

## 一、为什么计算书不能当证据

计算书是「程序**说自己**怎么算」，代码是「程序**实际**怎么算」。两者会不一致，已经抓到实例：

| 量 | 计算书模板 | 代码实际 |
|---|---|---|
| 立柱挠度 | `5q_kL⁴/384EI·(1−2.4(A/L)²)` | `[5−24(A/L)²]·q_k·L⁴/(384EI)`（`0x1D681D0 fmul 24.0` → `0x1D681D6 fsubr 5.0`） |

模板等效 `5−12x²`，代码是 `5−24x²`；`A=0` 时两式相同，所以单跨对拍一直没暴露。
⇒ **模板只能用来给分支贴标签，不能用来推公式。**

## 二、数据真实传递的三个事实（立柱函数实测）

### 1. 所有输入都从窗体对象读，函数没有数值入参

函数头 `0x1D443B0`：

```asm
01D443B7  mov eax, [ebp+8]        ; 唯一参数 = Form 对象（VB6 的隐藏 this）
01D443BA  mov eax, [eax]          ; vtable
01D443BF  call [eax+0x74c]        ; 方法
01D443CF  movsx eax, word [eax+0x58]
01D443D3  test eax, eax
01D443D5  jne  0x1D443DC
01D443D7  jmp  0x1D70415          ; field58 == 0 → 直接跳出（该分支不适用）
```

⇒ **分支开关是 `Form->field58`**；不适用就整段跳过。这就是"同一函数里塞了所有构件类型"的实现方式。

### 2. 取值走 COM 属性 + VARIANT 转换

```asm
01D4469F  lea eax, [ebp-0x4f8]    ; 目标 VARIANT
01D446A5  push eax
01D446AC  mov eax, [ebp-0x8a8]    ; 对象
01D446AC  mov eax, [eax]          ; vtable
01D446B4  call [eax+0xa0]         ; ← 读属性，结果写进 VARIANT
01D446F5  push [ebp-0x4f8]
01D446FB  call 0x419E38           ; VARIANT → double
01D44700  fstp [ebp-0x320]        ; q = 结果
```

`0x1D44700` 是 **q 的唯一一次写入**，之后被读 67 次、参与读改写 38 次。
⇒ q 不是这个函数算出来的，是**从对象属性读进来的**。

### 3. 所有输出都是"算完 → 立刻取整"的两个复用槽

189 处定稿点，模式完全一致：

```asm
fstp  qword ptr [ebp-0x510]   ; 原始值（未取整）
mov   dword ptr [ebp-0x518], 5   ; vt=5 (VT_R8)
push  3                          ; 位数
lea   eax, [ebp-0x518] ; push eax
lea   eax, [ebp-0x528] ; push eax
call  0x419DDE                   ; ← rtcRound(src, dst, 3)
call  0x419C58                   ; VARIANT → double
fstp  qword ptr [ebp-0xfc]       ; 取整后的值
```

- `ebp-0x510` = **当前量原始值的通用暂存**（每算完一个量就写一次）
- `ebp-0xfc` / `ebp-0x3e8` = **取整后的落地槽**（供后续引用/输出）

⇒ 不能靠槽号区分量，只能靠**分支位置**。这是这个函数"189 个定稿点、槽号全重复"的原因。

---

### 2.2 输入通道 = 17 个 vtable 槽（全部输入都从这里进来）

扫全函数 `call dword ptr [reg + 0xNNN]`，只有 **17 个不同的槽**：

| vtable 槽 | 次数 | vtable 槽 | 次数 |
|---|---|---|---|
| `+0x370` | 186 | `+0x314` | 4 |
| `+0x028` | 93 | `+0x0F0` | 4 |
| `+0x068` | 93 | `+0x374` | 4 |
| `+0x744` | 50 | `+0x74C` | 1 |
| **`+0x0A0`** | **48** | `+0x310` | 1 |
| `+0x31C` | 45 | `+0x0E0` | 1 |
| `+0x740` | 45 | `+0x330` / `+0x334` | 1 / 1 |
| | | `+0x318` / `+0x748` | 1 / 1 |

**`+0x0A0` 是取数值用的通用槽**（48 次）。两个最关键的输入都走它，但**源对象不同**：

```asm
; 位置 A = ebp-0x320（源对象取自 vtable +0x314）
01D443EB  call [eax+0x314]   ; 取对象 A
01D443FE  mov  [ebp-0x8a8], eax
01D446B4  call [eax+0x0A0]   ; 取属性 → VARIANT
01D446FB  call 0x419E38      ; VARIANT → double
01D44700  fstp [ebp-0x320]   ; ← 位置 A

; 位置 B = ebp-0x358（源对象取自 vtable +0x334）
01D4472B  call [eax+0x334]   ; 取对象 B
01D44759  call [eax+0x0A0]   ; 同一个属性槽
01D447A0  call 0x419E38
01D447A5  fstp [ebp-0x358]   ; ← 位置 B
```

### 2.3 命名修正：不要再叫 `q`

之前把 `ebp-0x320` 叫 `q`（线荷载），**这是按公式位置猜的，不是证据**。修正为：

| 符号 | 事实（代码位置） | 语义假设（**待确认**） |
|---|---|---|
| `A = ebp-0x320` | 只写 1 次（`0x1D44700`），只参与 `/E /I` 类算式 | 标准值荷载（挠度用） |
| `B = ebp-0x358` | 只写 1 次（`0x1D447A5`），参与 `a²/2`、`L²/2` 等**内力**算式 | 设计值荷载（强度用） |

「A 进挠度、B 进内力」是**代码事实**；「A=qk、B=qd」目前只是假设，需运行时确认。
两者的取值方式完全相同（同 vtable 槽、同转换函数），差别只在源对象（`+0x314` / `+0x334`）。

### 2.4 这条链的静态边界

`call [eax+0x0A0]` 的目标在 **VB6 运行时的控件实现**里（`ThunderRT6*` 系列），不在本 EXE 内。
⇒ 静态分析到"槽号"就到底了；要拿到属性名必须**运行时解析**（读对象的 vtable → 函数地址 → 反查 DLL 导出）。

镜像里确实有 VB6 类型库结构（例：`0x427804` 附近能读出 SSTab 的 `BackColor` / `ForeColor` / `Caption` 名字数组 + GUID `04746E60-…`），
但 Form 自身的方法名表尚未定位。

### 第 1 步：枚举定稿点

所有 `call 0x419DDE`（`rtcRound`）= 一个输出量的终点。
→ 脚本 `v35_round_points.py` 输出「定稿地址 / 位数 / 原始值栈槽 / 取整后栈槽」。

### 第 2 步：建栈变量读写索引

`v35_varflow.py build` 顺序反汇编整函数（43,566 条指令），
按 `[ebp±disp]` 建「写 / 读 / 读改写」索引（591 个变量）。
查询：`var --off -0x320` 立刻看到某变量**所有**读写点。

### 第 3 步：还原算式骨架

对每个定稿点回溯到上一个定稿点，按浮点指令序列还原：

```
fld [const]; fld [var]; call Pow(0x419E6E)   →  Pow(var, const)
fmul/fdiv/fsubr/fadd [X]                     →  *X  /X  X-  +X
```

→ 脚本 `v35_formula_points.py`，输出如 `Pow(3,a) *q /3 /E /I`。

**已确认的运行时函数地址**（从代码用法反推，非猜测）：

| 地址 | 作用 | 判据 |
|---|---|---|
| `0x419DDE` | `rtcRound(src, dst, digits)` | 189 处，前面必 `push 3` + `vt=5` |
| `0x419C58` | VARIANT → double | `rtcRound` 之后紧跟，`fstp` 落地 |
| `0x419E38` | VARIANT → double（另一入口） | q 的取值链 |
| `0x419E6E` | `Pow(base, exp)` | 前面必压两个 double |
| `0x419AE4` | 除零保护除法 | 前有 `cmp [0x220d000],0` 分支 |

## 四、第一批结果：立柱函数的算式骨架（189 个定稿点）

完整清单：`local-data/recon/slots/column_formula_points.txt`

### 4.1 已能确定「谁进哪个式子」的定稿点

下表只陈述**代码事实**：`A`=`ebp-0x320`（0x1D44700 写入），`B`=`ebp-0x358`（0x1D447A5 写入）。
`A` 只出现在除以 `E`、`I` 的式子里；`B` 只出现在**不除** `E`、`I` 的式子里——这正是"标准值算变形 / 设计值算内力"的分工。

| 地址 | 还原出的算式 | 数学形式 | 用谁 |
|---|---|---|---|
| `0x1D44FFA` | `Pow(3,a)·A /3 /E /I` | `A·a³/(3EI)` | **A** |
| `0x1D47186` | `Pow(4,a)·A /8 /E /I` | `A·a⁴/(8EI)` | **A** |
| `0x1D48A3F` | `L·Pow(3,L)·A·(L−v) /24 /E /I` | `A·L³(L−x)/(24EI)` | **A** |
| `0x1D467DA` | `(L−v)·Pow(2,L)·A·(L+v) /6 /E /I` | `A·L²(L−x)(L+x)/(6EI)` | **A** |
| `0x1D68248` | `[5−24(a/L)²]·A·L⁴/(384·E·I)` | 跨中挠度 | **A** |
| `0x1D46ECC` | `Pow(2,a)·B /2` | `B·a²/2`（悬挑弯矩） | **B** |
| `0x1D485F4` | `Pow(2,L)·B /2` | `B·L²/2` | **B** |
| `0x1D458B1` | `1 + B·a·L /2` | 支座反力型 | **B** |

⚠️ `0x1D68248` 那条与计算书模板的 `(1−2.4(A/L)²)` 冲突，**以代码 `5−24x²` 为准**。

### 4.2 中间量（几何/静矩类，133 个不含 E、I 的点）

典型：`*a *a`（a²）、`*L *L`（L²）、`Pow(2,a)*v(-856)/2`、`*a +L +L SUB-2 /2`（(L+a)²/2 型）
—— 这些是外伸梁的弯矩/剪力分量，逐个对应到经典解即可，不需要文案。

### 4.3 还没定位到的

| 量 | 状态 | 下一步 |
|---|---|---|
| `σ = M/W` 的**代码位置** | 未定位。已排除：133 个不含 `/E /I` 的点里没有 `÷W` 形态 | 找 `W` 从 COM 读出的槽（像 q 一样），再找它的 `fdiv` 引用 |
| `M = qL²/8` 的**单跨**版本 | 只见外伸/多跨版本（`/8` 的 37 处引用都在 `0x1D47xxx` 之后） | 继续按骨架筛 |
| `τ = V·S/(I·t)` | 未定位 | 特征：`÷I ÷t` 且乘 `S` |
| `qk → qd` 的 ×1.5 | 未定位（q 是外部读入，说明 qk/qd 在**另一个函数**里算好） | 追 q 的来源属性（`[eax+0xa0]`）对应窗体哪个控件/字段 |

**已排除的候选（省得重走）**

- 全函数被当**除数**的栈变量只有 5 个：`-0x4f0`(E)×56、`-0x4b4`(I)×56、`-0x2c8`(L)×39、
  `-0x14c`(-332)×10、`-0x3b0`(a)×1。
- 其中 `-0x14c` 一开始怀疑是抵抗矩 `W`，实测**不是**：它在 `0x1D4FB25` 由 COM 属性读入，
  紧接着 `0x1D4FB67` 起是 `Pow(v,2)·v(-0x358)·a / v`，再 `fsubr 1.0` → 形态是 `1 − v·X·a`，
  是**系数类**（薄膜/折减），不是 `M/W`。
- `-0x358`(-856) 被 `fmul` 39 次，是高频系数，未定名。

## 六、纪律（本次确立）

1. **公式只认代码**：模板/计算书文字仅用于给分支贴标签，不参与推导；
2. **不反推**：取值只来自 ① 代码 ② 数据文件 ③ 程序状态直读（槽数组/内存）；
3. **每个结论必须给地址**：没地址就是"未定位"，不写成"已确证"；
4. **先有工具再挖**：一次建好索引，后续每个量都是查询而不是重新读汇编。
