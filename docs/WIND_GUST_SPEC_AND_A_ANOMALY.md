# 阵风系数 βgz 与风荷载放大系数 β —— 规范依据、逐步对拍与错因定位

取证日期：2026-10-24（**已更正**，前版结论有误，见文末「错因复盘」）

对象：V35 脱壳镜像 `unpacked_runtime.exe`、V31 运行实例、复刻 SMHS、GB50009-2012 / GB55001-2021

---

## 一、结论先行（唯一正解）

围护结构（幕墙）风荷载里进 wk 的不是 βgz，而是：

```
β = max( βgz , 1 + 0.7/√μz )
βgz = 1 + 2·g·I10·(z/10)^(−α)
```

| 量 | 取值 | 出处 |
|---|---|---|
| g 峰值因子 | **2.5**（广东规范 3.0） | GB50009-2012 8.6.1 条文说明；V35 常量 0x401F18 / 0x401F68 |
| I10 湍流度 | A 0.12 / B 0.14 / C 0.23 / D 0.39 | 同上；常量 0x401EF8–0x401F10 |
| α 地面粗糙度指数 | A 0.12 / B 0.15 / C 0.22 / D 0.30 | 同上 |
| 截断/梯度高度 | A[5,300] B[10,350] C[15,450] D[30,550] | GB50009-2012 条文说明 8.2.1；V35 0x511720–0x511848 |
| **β 下限** | **1 + 0.7/√μz** | **GB55001-2021 第 4.6.5 条第 2 款** |

> GB55001-2021 4.6.5-2 原文：「围护结构的风荷载放大系数应根据地形特征、脉动风特性和流场特征等因素确定，
> **且不应小于 1+0.7/√μz**，其中 μz 为风压高度变化系数。」

**复刻原先漏的就是这条下限**（只算了 βgz），导致 A 类偏低 0.93%。

## 二、为什么只有 A 类表现出来

把下限改写成同一形式：因 μz = C·(z/10)^p，故

```
1 + 0.7/√μz = 1 + (0.7/√C)·(z/10)^(−p/2)
```

两式指数相同（p/2 = α 恒成立），差别只在系数：

| 类 | 0.7/√C（下限系数） | 2·g·I10（βgz 系数） | 谁大 | 实测 β |
|---|---|---|---|---|
| A | 0.7/√1.284 = **0.6178** | 2×2.5×0.12 = 0.6000 | 下限 | 取下限 |
| B | 0.7/√1.000 = 0.7000 | 2×2.5×0.14 = 0.7000 | 相等 | 两式同值 |
| C | 0.7/√0.544 = 0.9490 | 2×2.5×0.23 = 1.1500 | βgz | 取 βgz |
| D | 0.7/√0.262 = 1.3675 | 2×2.5×0.39 = 1.9500 | βgz | 取 βgz |

⇒ 只有 A 类会被下限压过，B 类恰好相等，C/D 类由 βgz 主导。**这解释了「只有 A 类差 0.93%」的全部现象。**

## 五、补一条：原程序三份实现的一致性

V31 里 `1+2*` 模板串被 **10 处**代码引用，归为三份实现：

| 模块 | 地址 | 算术风格 | g 来源 | 系数 | 结论 |
|---|---|---|---|---|---|
| ① | 0x85E209–0x85E334（A/B/C/D 在 0x85E/0x85E9/0x85EF/0x85F4） | VARIANT thunk（`__vbaVarMul/Div/Pow`） | `slot[76]`=2.5（0x85DEF8 `fld 2.5`） | `fld [0x401998]`=0.12 | 与规范公式同构 |
| ② | 0x14762xx（A）/0x14766xx（B）/0x1476Axx（C）/0x1476Exx（D） | x87 原生 + `call 0x41376e`(pow) | `[ebp-0x38]` = 0x4019A0(2.5) 或 0x4019A8(3.0) | `fld [0x401998]`=0.12 | 同上 |
| ③ | 0x1B25xxx | x87 原生 | 同上 | 0.12 | 同上 |

三份**都只算 βgz = 1+2·g·I10·(z/10)^-α**，都没有在下限上做文章；
下限 `1+0.7/√μz` 是在**取用 β 的那一层**（wind 组装处）做的，因此三处实现看起来「都对」，而结果偏大。

V35 与 V31 的 ① 号实现做过归一化事件比对：**20/20 事件完全同构**（见 `compare_gust_block.py`）。

## 六、错因复盘（重要，避免再犯）

### 6.1 曾经的错误结论

前版本文档写的是：「A 类实算系数 0.6178、等效 I10=0.12356、程序文案与实现不符」——
**这是错的**。0.6178 不是 I10 变体，而是 `0.7/√1.284` 恰好等于 0.61776：
下限项与 βgz 项同指数，所以把下限误当成「系数不同的 βgz」在代数上完全说得通，导致看起来像"程序改了 I10"。

### 6.2 真正的错误链

1. 一开始只对比 **两端结果数字**（V31 wk 2.029 vs 复刻 2.011），看到 0.9% 就归因「V31 与文案不符」；
2. 后来补了「按 z=10 读系数」，得到 0.6178，进一步**强化**了错误结论（因为那时还没有把下限项纳入候选）；
3. 最后靠**逐步拆解整条链**（① z/10 → ② 幂 → ③ 系数 → ④ βgz → ⑤ μz → ⑥ 下限 → ⑦ max），
   七个实测点同时约束，才发现 ⑥ 这一项才是主导，而 βgz 本身一直是 0.12，从没变过。

### 6.3 教训（已写入项目铁律）

- 只看两端数字、不看中间取值 → 挖不到位；
- **「一个因变量异常」必须把所有候选加项列全再拟合**，不能只盯着最像的那一项；
- 代数等价的不同写法（βgz vs 0.7/√μz）在数值上无法区分，**必须回到规范条文找有没有第二条式子**。

## 十、IDA / Hex-Rays 复核（2026-10-24，补 V35 代码级证据）

前几轮 β 下限是靠「7 个实测点 + 规范条文」推出来的，**没有在 V35 代码里看到那条 0.7**。
本轮用 IDA（ida-mcp / idalib 后端）补齐：

### 10.1 `0.7` 常量的引用点就在风荷载模块

`0x401EA8`(0.7) 在 V35 内被引用点中包含 **0xA717A1**；`0x401EA0`(0.5) 在 **0xA717DE**。
两者都在风荷载过程体内（0xA6E000–0xA74000）。

反汇编 `0xA7179F–0xA71894`：

```
0xA7179F  fld qword [0x401EA8]       ; 0.7
0xA717DC  fld qword [0x401EA0]       ; 0.5
0xA71847  call __vbaVarPow           ; Pow(slot[10], 0.5)   ← slot[10] 实测 = μz(2.2313)
0xA71854  call __vbaVarDiv           ; 0.7 / √μz
0xA71861  call __vbaVarAdd           ; 1 + 0.7/√μz
0xA71883  call __vbaR8Var            ; Variant → double
0xA71894  call 0xA582CD              ; ★ max(double, double)
```

### 10.2 `0xA582CD` 的 Hex-Rays 伪代码 = max

建函数后（0xA582CD–0xA58367）反编译：

```c
_DWORD *__stdcall sub_A582CD(_DWORD *a1, double a2, double a3)
{
  ...
  if ( a2 <= a3 )  v5 = a3;
  else             v5 = a2;
  ...
}
```

**⇒ V35 原程序就是 `β = max(βgz, 1 + 0.7/√μz)`**，与 GB55001-2021 4.6.5-2 一致，
不是复刻按数值拟合出来的。

### 10.3 βgz A 块伪代码（0xA702E0）

```c
*(double *)(a1-556) = dbl_401F10;      // 0.12（I10，同时是 α）
*(a1-564) = 5; *(a1-572) = 10; *(a1-580) = 2;
*(double *)(a1-588) = -dbl_401F10;     // -0.12
*(a1-596) = 5;
vb6_vbaVarMul(a1-356, 16 * *(a1-732) + dword_220D178);   // × slot[76] = g
v2 = vb6_vbaVarMul(a1-372, a1-564);    // × 0.12
v3 = vb6_vbaVarDiv(a1-388, a1-580, a1-44, v2);           // z / 10
v4 = vb6_vbaVarPow(a1-404, a1-596, v3);                  // ^ -0.12
v5 = vb6_vbaVarMul(a1-420, v4);
v6 = vb6_vbaVarAdd(a1-436, v5);                          // + 1
vb6_rtcRound(a1-452, v6);
*(a1-728) = 8;                                           // → slot[8]
```

与逐指令分析完全一致：`βgz = Round(1 + 2·g·I10·(z/10)^(−α), 4)`。

### 10.4 IDA 使用限制（记录备查）

- 风荷载主过程体量巨大（`0xA62C07` 起，到 `0xA84006` 约 136 KB），**Hex-Rays 整函数反编译返回 None**；
  只能对**小块**（如 0xA702E0 的 βgz 块、0xA582CD 的 max 助手）反编译成功。
- 该区段 `0xA62C07` 之后到 `0xA72000` 之间**没有任何 `55 8B EC` 序言**，说明确实是一个巨型过程，不是多个小函数。
- 后续若需整段伪代码，思路：按基本块切分成多个小函数再分别反编译。
