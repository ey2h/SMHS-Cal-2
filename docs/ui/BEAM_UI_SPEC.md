## 3. 栅格与尺寸规范

### 3.1 垂直分区（客户区 442）

| 区 | 高度 | 计算 |
|---|---|---|
| 标题条 | 19 | 固定，同立柱屏 |
| 计算依据带 | 39 | 上边距 11 + 内容 28（`Padding 10,6,10,7` + 行高 15） |
| 主区 | **319** | `442 − 20 − 64 − 39`（弹性区，吸收换行/缩放误差；含上间距 10 → 面板实高 309） |
| 按钮区 | 64 | `Padding 8,6,8,4` + 24 + 6 + 24 |
| 状态栏 | 20 | `Padding 8,2` + 15 + 上边线 1 |

### 3.2 水平分区（936）

| 区 | 宽度 | 计算 |
|---|---|---|
| 外边距 | 8 + 8 | 主区 `Margin="8,10,8,0"` |
| 左：型材区 | 642 | `(936−16−8) × 1/(1+0.42) ≈ 642.3` |
| 缝 | 8 | 列定义里的固定 8px |
| 右：预演结果 | 270 | `912 × 0.42/1.42 ≈ 269.7`（≈ V31 的 264） |

| 场景 | 值 |
|---|---|

| 分区间水平缝 | 8 |
| Frame 内边距 | 左右 9 / 上 11（让开骑线标题）/ 下 6 |
| 控件之间（按钮、框） | 6 |
| 表格与摘要条之间 | 6 |
| 结果面板内边距 | 左 5 / 上 3（行距紧凑，1:1 V31 行高 15） |
| 空态文本内边距 | 10,8 |

### 3.4 型材表列宽（合计 616 ≤ 可用 622，留 6px 余量吸收竖向滚动条）

| 列 | 宽 | 列 | 宽 |
|---|---|---|---|
| 型材号 | 96 | Sx | 52 |
| Ix | 52 | Sy | 52 |
| Iy | 52 | tx | 48 |
| Wx1 / Wx2 | 52 / 52 | ty | 56 |
| Wy1 / Wy2 | 52 / 52 | | |

> 取值依据：最大数值 `123650`（6 位）在 11px 宋体 ≈ 37px + 单元格左右 Padding 8 = 45px，52 有余量；
> 型材号最长 `40/60系列`（3 汉字 + 4 数字）≈ 63px + 8 = 71，96 有余量。
> **列宽必须固定为像素**：本项目 `ColumnCalcView` 已记录「Avalonia DataGrid 的 `Width` 被当 Auto/0」的历史坑，

## 5. 状态设计

| # | 状态 | 触发 | 视觉表现 |
|---|---|---|---|
| S0 | **默认（未预演）** | 首次进入，`HasResults=false` | 结果面板保持 `#C0FFFF` 空底；`PlaceholderText` 以 `#6B6B6B` 左对齐贴顶显示（`10,8`）；状态栏 `StatusText` 为空则不占视觉重量；型材表默认选中首行（VM 构造时已选），选中行 `#C0FFFF`；截面摘要条已显示数值 |
| S1 | **预演成功** | `Results` 有行 | 结果面板内逐行渲染，行高 15 + 行间隙 1；`√` 行 `#0000C0`；面板底色**不变**（V31 不改底色，避免通过/不通过整块变色造成「新 UI」观感） |
| S2 | **预演不通过** | 某判定行 `×` | 唯一信号是该行 `#C00000` 文字 + `(×)` 符号；不加红框、不加图标、不改底色 |
| S3 | **结果失效** | 上游参数变化 → `Invalidate()` 清空 `Results` | 视觉**回到 S0**（同一套空态），差异只由状态栏文案承担：「上游参数已变化，请重新预演」|
| S4 | **未选型材** | `SelectedProfile=null` | 截面摘要条显示「（未选型材）」；点「预演」→ 状态栏「请先在型材表中选择一行」，结果面板不动 |
| S5 | **悬停/按下** | 指针 | 按钮 `#DEE7F5`（边变 `#2F6FED`）→ 按下 `#C8D6EA`；表格行 `#E4F5F5`；输入框悬停/聚焦边变 `#2F6FED` |
| S6 | **禁用** | （本屏暂无） | `#EDEDED` 底 + `#C8C8C8` 边 + `#9A9A9A` 字（全局 `Button:disabled` 已内置，含内嵌 TextBlock 变灰）；将来 VM 提供 `PreviewEnabled` 时直接 `IsEnabled="{Binding PreviewEnabled}"` |

## 6. 自适应策略

### 6.1 主策略：固定窗体 + 居中（默认，推荐）

沿用立柱屏已确立的形态——**固定尺寸窗体浮在 MDI 绿底客户区中央**，这也是 V31 的 MDI 子窗体行为：

| 分辨率 | 客户区可用（扣菜单条 ~22 + 底部状态栏 24） | 窗体 936×461 | 留白 |
|---|---|---|---|
| 1280 × 800 | 1280 × 754 | 936 × 461 | 左右 172 / 172；上下 146 / 147 |
| 1920 × 1080 | 1920 × 1034 | 936 × 461 | 左右 492 / 492；上下 286 / 287 |

两种分辨率下**窗体尺寸不变**，只有四周留白变化。这样做的三个理由：
1. 与立柱屏同屏切换时窗体不跳动（这是用户最能感知的一致性）；
2. 横梁表 11 列是密集数值表，宽度一旦放大，列宽放大反而让「一眼扫一列」变难；
3. 横向拉伸会让结果面板变宽，`#C0FFFF` 大面积空底+短行文本的观感会明显变差（V31 的 264px 是刻意的窄栏）。

阈值：视口宽度 < 968（936 + 2×16）时，宿主 `ScrollViewer` 出滚动条，本视图不改行为。

### 6.2 备选：宽屏拉伸模式（需宿主配合，本次不启用）

若产品要求「吃满宽屏」，改动只有两处，且**不需要动本视图的内部结构**：

```xml
<Border MinWidth="936" MinHeight="461" Background="#F0F0F0">  <!-- 去掉 Width/Height -->
```
并把 `Views/Calc/CalcMainWindow.axaml` 中 `FormHost` 的 `HorizontalContentAlignment` 从 `Center` 改为 `Stretch`。

此时内部比例栅格自动生效：

| 分辨率 | 左区 | 结果区 | 说明 |
|---|---|---|---|
| 1280 | ≈ 884 | ≈ 371 | 表格 616 列宽 → 右侧留白 ≈ 250（需把 `ty` 列或所有数值列改星号宽才好看） |
| 1920 | ≈ 1256 | ≈ 528 | 留白 ≈ 620，观感明显变空 |

**风险提示**：星号列在本项目有「宽度不生效」的历史记录（见 `ColumnCalcView` 第 169 行注释），启用拉伸前必须先做一次列宽实测，否则会出现整表塌陷。因此默认交付固定窗体形态。

### 6.3 高 DPI

按 1px 边框 + 15px 行高的像素级复刻，100% 缩放为基准。125%/150% 下由 Avalonia 统一缩放，1px 边框会被渲染为 1.25/1.5px（发虚但不错位），**不做补偿**：补偿（如把边框改成 0.8）会在 100% 下丢失边线。

## 7. 任务流与可读性设计

| 用户意图 | 界面引导 |
|---|---|
| 「我要算这个型材」 | 表格默认选中首行（40/60），选中即高亮，右侧立刻可预演 |
| 「我要找某个型号」 | 检索行：`型材代号` 水印框 + 左侧「快速查找型材」按钮（V31 的按钮在左、框在右，肌肉记忆保留）；命中后状态栏反馈「定位型材：xxx」 |
| 「我要知道用了什么参数」 | 计算依据带一行给全 B/H/wk/g/αmax；结果面板首段固定是「风荷载标准值为…」，与 V31 输出 1:1 |
| 「够不够」 | 结果面板每段末尾一行 `满足要求(√)` / `不满足要求(×)`，蓝/红一色定论；不需要用户自己比数 |
| 「下一步干什么」 | 按钮 2×2 常驻右下角，位置不随内容变化 |
