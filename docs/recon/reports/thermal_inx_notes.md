## 6. unknowns（含义未经证实的字段/结论）

1. `thermal_zone`（50176 组字段2）：形如 `1A/1B/1C/2A/2B/3A/3B/4A?` 的代号，疑似《GB 50176 热工规范》的建筑热工设计分区代号（ⅠA/ⅡA/ⅢA…），但源文件本身没有给出代号定义，也没有表头。仅“取值形态 + 目录名 50176”支持该推测。
2. `altitude`（字段3）：与海拔量级一致（上海=3、呼和浩特=1065、甘孜地区值上千），但未在源文件中看到单位“m”的说明。
3. `jan_mean`（字段4）/`daily_min`（字段5）：带符号、1 位小数，且 50176 组内 f5 ≤ f4 恒成立；具体物理含义（1 月平均温度 / 最冷日平均温度 / 采暖室外计算温度 …）无源内证据。列名只是按任务要求暂定的占位名。
4. `leiji` 组字段2：全为正值（范围见上），随海拔/纬度增大；可能是累年某指标（如“累年1月平均温度绝对值×?”“冻结指数”“度日数”），源内无表头，含义完全未证实。
5. 文件名代号（ah/bj/gd/hainan/hbei/hlj/hn/nmg/nx/qh/sc/sd/sh/sx1/sx2/tj/xj/xz/yn/zj/…）与省份的对应关系为推测：例如 `sx1`/`sx2` 可能表示同一省被拆成两个分区（如山西/陕西? 或内蒙两区?），`hbei`/`hn`/`hb` 可能分别是河北/河南/湖北或华南/湖南，存在歧义，需人工核对。
6. leiji 组中出现的名称包含 `酉阳县（钟名镇）`、`达川市`、`渡口市`（旧地名）等，说明数据源年代较早；同一城市在两组的名称写法可能不同（如 `西昌市` vs `西昌`），因此按名称做 join 不稳妥。
7. 这些数值被程序如何使用（哪个计算模块读取哪一组文件）未确认——需要看主程序调用（可用 REA/PE 分析，但本次未做）。
