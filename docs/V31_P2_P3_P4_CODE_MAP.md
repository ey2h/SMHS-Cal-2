### 1.3 三个「必须照抄代码」的坑

1. **锚筋面积的两个分支构成不同**（不是简单取大的 M 项）：
   - 分支1 = `V项 + N项 + M/(1.3αb·fy·z)` = 9.9617+42.8455+4.6357 = **57.443**
   - 分支2 = `　　　 N项 + M/(0.4αb·fy·z)` = 42.8455+15.0659 = **57.911** ← 实机取此
   - 分支2 **不含剪力项**。按「两分支同构」写会得 67.873，被测试逮住。
2. **荷载类取 6 位、应力类取 3 位**：组合荷载 0.0021515 若按 3 位取整成 0.002，轴力从 7098.3 掉到 6600。
3. **两处「除以 2」**（转接件强度、转接件挠度、焊缝强度各一次）：数值确证无疑，
   物理上应是「两侧对称连接件各担一半」，但界面无对应开关 ⇒ **语义未定位**，按算式保留并标注。

### 1.4 未定位

- 转接件截面特性（A=1274.8 / W=39700 / I=1980000）由「焊缝和转接件参数」帧的型钢规格算出，
  复刻版暂作为输入；接截面特性模块后应由其提供。
- 「受力方式」帧在实机是 SSTab + 4 张 PictureBoxDC 示意图，复刻版用几何输入框替代（不影响数值）。
- 后补锚栓 / 槽型埋件 / 对穿螺栓三种埋件种类未复刻（当前只做土建预埋）。

## 三、计算书（P4）

- `CalcBookWriter`：手写最小 OOXML（zip 三件套 + `word/document.xml`），不依赖 DocumentFormat.OpenXml。
  支持 H1/H2/H3/正文/**表格**/分页 六种块；表格生成单线边框 `w:tbl`，
  **必须带 `<w:tblGrid>`**（缺了 Word 会弹"内容有问题"，python-docx 直接抛 InvalidXmlError）。
- `CalcBookComposer`：按 V31 章节顺序组装 封面 → 设计依据 → 风荷载 → 立柱 → 横梁 → 玻璃 → 连接 → 埋件 → 胶类 → 结论。
  **缺章写「本章未参与计算」，不编造数字。**
- **九章全覆盖**：立柱/横梁/玻璃三章取自各屏预演的文本摘要（`CalcSession.SummaryOf` 丢掉分隔线与空行），
  连接/埋件/胶类三章取自引擎结果结构体。**没预演过的屏会自动补跑一次**（失败则该章写"本章未参与计算"，不阻断出书）。
- 入口：
  - 界面：胶类屏「下一步」= 生成计算书（写到 `计算书输出/计算书_<时间戳>.docx`）
  - 命令行：`dotnet run -- --calc --calcbook=<path>`（加 `--v31sample` 用 V31 对拍工程那组参数：
    支承口径 1.285 / 面板口径 1.37 / 1100×1380 / 支点 3000）
- 排版：连接/埋件/胶类三章改为 **7 张表格**（连接 1 + 埋件 4 + 胶类 2），规范条文仍为正文段。
- 第三方校验：`python-docx` 能完整解析（52 段落 / 7 表格 / 4.6 KB），表头与值逐格正确。
- 验收：`CalcBookTests` 4 条 —— 各章数值与引擎逐位一致、缺章不编造、结论按验算结果给、docx 结构合法（zip 三件套 + 关键数字落在正文）。
- 样例：`计算书输出/计算书_V31对拍样例.docx`，22 个关键数字与 V31 计算书原文逐位一致；
  九章均有内容（立柱 17675mm³ / 横梁 904.139mm³ / 玻璃 24.793MPa / 连接 0.166·6660·633.889 /
  埋件 1716·7098.3·137280 / 胶类 6.121·5.475·43.907 / 结论"各项验算均满足规范要求"）。
