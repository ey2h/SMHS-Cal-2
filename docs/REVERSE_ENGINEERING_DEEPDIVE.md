# 汇宝 V35 逆向 · 深挖阶段结论（2026-10-22）

> 目标：把"计算逻辑"从程序里挖出来。CSV/参数库只是数据层，真正计算算法与前端操作在程序代码内。
> 本阶段在**不触碰注册/不脱壳破解**前提下，对 EXE 与周边文件做了合规静态深挖，结论如下。

## 1. 程序本体：VB6 + 多重壳，代码层静态不可达

| 文件 | 壳 | 说明 |
|---|---|---|
| `MQJSSV35.EXE` | **ASPack** | 主程序，**VB6**（导入含 `msvbvm60.dll`）。`.text` 段 `RawSize=0`（代码压缩进 `.aspack`）。导入表仅 KERNEL32/USER32/GDI32（壳导入）。 |
| `汇宝软件参数库转换及截面工具箱V35.exe` | **ASPack** | VB6，含"截面工具箱"，同样压缩。 |
| `Reg.dll` | **VMProtect (vmp0/1/2)** | 注册模块，强壳保护。**按计划 B1 红线，绝不触碰。** |
| `PDF规范阅读器.exe` | 无壳 | VB6（`vb6chs.dll`），仅 PDF 阅读，不含幕墙计算逻辑。 |

- **PE 节**：`.text`(0) / `.data`(0) / `.rsrc0`(0) 三节 RawSize=0 → 真实代码在壳里。
- **Overlay**：文件 `0x405000` 起到结尾 **9,157,514 B = 68.5%** 是 ASPack 压缩的原程序。全文搜索 `object / TForm / Borland / Delphi / 中文串 / GB·JGJ 规范` 命中数 **全部为 0** → 原程序（代码+资源+DFM+字符串）完全在压缩壳内，**磁盘静态分析拿不到任何计算逻辑或前端界面**。
- **更正此前假设**：此前按 DFM 迹象疑似 Delphi；现经导入表确认主程序为 **VB6**（非 Delphi），反编译工具链应改用 VB6 反编译器（如 VB Decompiler）而非 Ghidra/Delphi 路线。

## 3. 模板层：mmbk.CAM 仅是封面外壳

- `jss/mmbk.CAM` 与 `jss/模板.doc` 字节完全相同（24064 B），是 **Word 97-2003 模板**（OLE，无 VBA 宏，未加密）。
- 标题属性 GBK = `汇宝软件模板`，作者 = `罗英`。
- 用 Word COM 转 docx 后仅含 **10 段落（工程名称/设计计算书/设计·校对·审核·批准/公司名称/日期/目录）**，**0 表格、0 书签、0 域** → 真实计算书章节/表格/计算字段由程序**运行时动态生成注入**。模板只是封面与目录框架。

## 4. 代码层（计算算法）的获取路径 —— 必须 B3 授权

要把"前端操作如何触发计算、荷载组合/内力/面板/连接/埋件/胶缝等算法"还原，唯一途径是**动态脱壳 / 内存转储**得到解压后的 VB6 程序，再用 VB6 反编译器分析：

- **B3 规定**：动态脱壳、内存转储、注册绕过等动作需用户**逐次明确授权**，且本机当前**无 Ghidra + JDK 21**（REA 原生反编译依赖），也**无 VB6 反编译器**。
- **REA 状态**：`rea-agents@6.7.0` 已写入 `~/.workbuddy/mcp.json`，但**尚未在连接器页"信任"激活**（工具列表无 `mcp__rea__*`）。即便激活，对加壳 VB6 也需先脱壳。
- **纯静态已到底**：壳/overlay/数据层/模板层已挖尽；代码算法层静态不可达，到此必须决策是否进入 B3。

## 5. 边界（重申计划 B1 / B3）

- **B1**：不碰注册绕过、不脱壳破解、不制作注册机；`Reg.dll`(VMProtect) 红线不越。
- **B3**：任何动态脱壳 / 内存转储 / 运行时分析，须用户**逐次明确授权**，且对象为用户**合法拥有/获授权**的软件，目的限于研究、互操作、软件保存。

## 6. 下一步决策点（待用户）

- **(A) 授权 B3 动态脱壳**：在本机运行汇宝 + 内存转储解压后的 VB6 程序 → 用 VB6 反编译器 / REA 还原计算逻辑与前端变量。需要：用户授权 + 信任 REA + 安装 Ghidra+JDK21（或 VB6 反编译器）。
- **(B) 继续数据层深挖（合规、无需 B3）**：解析 `A0xx.CAM` 语义、`guifan.dat` 各系数精确含义、热工 inx 字段映射；拆解 WMF 图元还原"四类图"；补 `param_library_gap.md` 的 P0 缺口列。
- **(C) 计划③模板拆解**：已确认 mmbk.CAM 是封面外壳，真实计算书由程序生成，故③的"拆模板"价值有限，应转向"黑箱对照"（需正版运行环境导新计算书作金标准）。
