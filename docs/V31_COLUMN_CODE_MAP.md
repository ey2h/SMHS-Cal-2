# V31 立柱计算函数：代码级数据流与算式还原

> 目标：把「每个输出数是怎么来的」从**代码**里挖出来，不看计算书、不做反推。
> 对象：V31 脱壳镜像 `local-data/recon/unpack/unpacked_v31.exe`
> 方法：常量 xref → 定函数包络 → 顺序反汇编 → 枚举 `rtcRound` 定稿点 → 符号执行还原算式。

---

## 一、函数定位（与 V35 同构，只差 244 字节）

| 项 | V31 | V35 |
|---|---|---|
| 函数 | `sub_18BD010` | `sub_1D442DA` |
| 地址范围 | `0x18BD010 – 0x18E9555` | `0x1D442DA – 0x1D70913` |
| 字节数 | **181,573** | 181,817 |
| 指令数 | 43,508 | 43,566 |
| 取整定稿点（`rtcRound`） | **189** | 189 |

定位方式：`384.0`（挠度分母）的 18 处引用中有 8 处落在该函数内；`2.5@0x4019A0`、`3.0@0x4019A8`
与旧记忆里的 V31 常量地址完全吻合，确认镜像正确。

**整函数 Hex-Rays 返回 None**（181KB 超出反编译器上限），所以走指令级。

## 二、★ 关键发现：一半的算术是 Variant 运算，不在 x87 上

第一轮统计「x87 除数」时只有 15 个栈槽（E/I/L/a 等），怎么都找不到 `W`。
原因是 **VB6 把这些量当 Variant 处理**，除法走运行时函数：

| stub | 导出名 | 立柱函数内调用次数 |
|---|---|---|
| `0x413708` | `__vbaVarDiv` | **138** |
| `0x413714` | `__vbaVarMul` | 41 |
| `0x41370E` | `__vbaVarPow` | 24 |
| `0x413552` | `__vbaVarAdd` | 24 |
| `0x41377A` | `__vbaVarSub` | 17 |
| `0x41371A` | `rtcRound` | 189 |
| `0x413624` | `__vbaR8Var` | 203 |
| `0x413738` | `__vbaR8Str` | 141 |
| `0x413750` | `__vbaStrR8` | 407 |
| `0x41369C` | `__vbaStrMove` | 1317 |
| `0x413672` | `__vbaStrCat` | 845 |

（名字来自 `msvbvm60.dll` 导出表：`slot值 − 0x734D0000` → RVA → EAT。
**不要再用 0x731F0000 当基址**，那是 comctl32。）

⇒ 这就是之前「σ=M/W 找不到」的根因：**W 作除数走的是 `__vbaVarDiv`，不是 `fdiv`**。

## 三、输入槽：都是界面上 TextBox 的文本

`__vbaR8Str` 紧接 `fstp qword [ebp-X]` 的模式 = 「控件文本 → double」。实测：

| 槽 | 读取次数 | 首处地址 | 含义（据算式推断） |
|---|---|---|---|
| `ebp-0x3B0` | 44 | `0x18BD861` | 外伸长度 A / 或分格宽（**待证**） |
| `ebp-0x4B4` | 44 | `0x18BDAD5` | 惯性矩 I |
| `ebp-0x2C8` | 34 | `0x18BE36A` | 计算跨 L |
| `ebp-0x14C` | 7 | `0x18C1F8A` | 总长 v |
| `ebp-0x2C0` | 5 | `0x18C2155` | （未定） |
| `ebp-0x320` | 1 | `0x18BD366` | 标准值线荷载 q_k |
| `ebp-0x358` | 1 | `0x18BD40B` | 设计值线荷载 q_d |
| `ebp-0x3F0` | 1 | `0x18BD4B0` | （未定，只读一次、被 44 个定稿点引用） |

**E 不是控件读入**（`-0x4F0` 不在上表），它走 `Form` 的属性 `[eax+0x748]` → Variant → double（`0x18BD4E2`）。

## 四、★ γ（截面塑性发展系数）是条件取值的——代码级

`0x18BD221`–`0x18BD2D8`：

```asm
; cond = ((flag89C == 0) || (flag8A0 == 1)) && (flag8A4 == 0)
cmp  word [ebp-89Ch], 0  / setz al / neg eax
cmp  word [ebp-8A0h], 1  / setz cl / neg ecx
or   ax, cx
cmp  word [ebp-8A4h], 0  / setz cl / neg ecx
and  ax, cx
...
jz   short loc_18BD2B3
fld  ds:dbl_4020E0       ; = 1.05
jmp  → VarMove 到 Variant [ebp-3A8h]
loc_18BD2B3:
fld1                     ; = 1.0
     → VarMove 到 Variant [ebp-3A8h]
```

- `dbl_4020E0 = 1.05` —— 就是 `σ = M/(γ·W)` 里的 **γ**
- 两个分支分别写 **同一个 Variant 槽 `-0x3A8`**，之后 44 个定稿点都引用它
- 判据是窗体上三个 `Integer` 标志（`-0x89C` / `-0x8A0` / `-0x8A4`），分别对应界面上决定
  「是否考虑塑性发展」的单选/复选状态

⇒ **γ 要么 1.05、要么 1.0，由界面开关决定**，不是固定值。复刻若写死 1.0（或 1.05）都只在特定组合下对。

## 五、189 个定稿点里已还原出算式的部分

产物：`local-data/recon/ida_out/v31_roundpoint_expr.tsv`
工具：`local-data/recon/v31_slice.py`（正向符号执行：x87 栈 + Variant 槽 + 调用名）

### 5.1 挠度族（含 `/E`、`/I`）——8 个，系数与规范两跨梁公式完全对上

| 点 | 地址 | 还原算式（`a`=`-3B0`，`L`=`-2C8`，`qk`=`-320`，`v`=`-14C`） |
|---|---|---|
| 005 | `0x18BF440` | `(a+L)·(3L²+4L+1) / 6 / E / I` |
| 013 | `0x18C16A5` | `(4 − L/(a+L)) / 24 / E / I` |
| 086 | `0x18D3511` | `[ (a+L)/2 − ((4(a+L) − 2(a+L))/2) ] · (q_k·v·L) / 24 / E / I` |
| 133 | `0x18DDD5C` | `(a/L + 1) / 3 / E / I` |
| 139 | `0x18DED6C` | `(2a/L + 3) / 6 / E / I` |
| 156 | `0x18E2146` | `(3a/L + 4) / 24 / E / I` |
| 162 | `0x18E3213` | `(a/L + 2) / 8 / E / I` |
| 166 | `0x18E415B` | `(4a/L + 3) / 12 / E / I` |

`(2a/L+3)/6`、`(3a/L+4)/24`、`(4a/L+3)/12`、`(a/L+2)/8` 是**外伸+单跨梁各特征点的挠度系数**
（GB 50009 附录的悬臂/带外伸梁公式），系数能一一对上，说明符号执行是对的。

### 5.2 弯矩族（含 `/8`）

| 点 | 地址 | 算式 |
|---|---|---|
| 060 | `0x18CD156` | `q_d · L · a · L / 8` |
| 065 | `0x18CE262` | 同上（另一分支） |
| 081 | `0x18D1DB3` | `(2 − L/(2a+L)) / 8` |

`q_d·L·a·L/8` 里的 `a` 若是**从属宽度**，则 `q_d·a` = 总荷载、`·L²/8` 就是简支梁跨中弯矩 ——
这正是之前一直没找到的「`M = qL²/8`」。**但 `-3B0` 到底是"外伸 A"还是"从属宽"尚未定**（见 §六）。

### 5.3 族 A：`f / (γ / X)` —— 共 43 个（最多的一族）

```
RP000  0x18BD9A6   f / (γ / (q_d · a))
RP002  0x18BE517   f / (γ / (((L+1)·q_d·a)·L/2))
RP004  0x18BF0F3   f / (γ / (q_d · L))
RP009  0x18C06FD   f / (γ / round3值)        ← 用上一轮的取整结果
```

`γ` 即 §四 的 Variant `-0x3A8`；`f` = `-0x3F0`（只读一次的那个控件值）。
这一族的语义**尚未定论**：`f/(γ/X)` 等价于 `f·X/γ`，究竟是「允许值反算」还是「预选」，
需要 §六 的一个运行时读数才能钉死。

### 5.4 其余

- 含 `/2` 的 10 个（如 `q_d·L·v/2`、`(L/(a+L) − 1)/2`）
- 「其他」47 个（如 `(L+a)`、`3L²+4L+1`、`(L/(a+L)+1)/3`）
- **未还原 78 个**：窗口内出现 `st?`（x87 栈里有未经我建模的入栈源，多为
  `__vbaVarAbs`/`__vbaVarTstGt` 之后的分支或三元表达式）

## 六、明确的缺口（不编，逐条给下一步）

| 缺口 | 现状 | 下一步（最小代价） |
|---|---|---|
| `-3B0` 是「外伸 A」还是「从属宽」 | 算式里既当长度（`a/L` 系数）又出现在 `q_d·a·L²/8` | **在 `0x18BD970` 下一个断点**，读 `[ebp-3B0h]` 与 `[ebp-2C8h]` 的 double 值，与界面输入对照，一次定死 |
| `-3F0` 的身份（族 A 的 `f`） | 只读一次，44 个定稿点引用 | 同上，`0x18BD945` 停一次读 `[ebp-3F0h]` |
| `VarDiv` 的左右操作数顺序 | 现按 `dst = args[-2] / args[-3]`（VB6 右到左压栈） | 断点处看 `-0x518` 与 `-0x528` 的实际值即可反证 |
| 78 个未还原定稿点 | `st?` | 补 `__vbaVarAbs` / `__vbaVarTstGt` / 三元分支的建模 |
| 对象访问器 `[eax+0x314/0x318/0x31C/0x330/0x334/0x370]` 对应哪个控件 | 已知是「窗体方法返回控件对象」 | 需 vtable 控件访问器顺序 ↔ 设计记录控件顺序 的映射 |

> **以上 5 条都指向同一件事：需要一个断点。** 一条 `0x18BD970` 的断点能同时解决前 3 条，
> 而这条断点在没有任何调试器的情况下做不了 —— 这是当前唯一硬卡点。
> 替代方案（无需调试器）：把 V31 的外伸/从属宽在界面上改成极端值（如 1 vs 10000），
> 观察哪些输出成比例变化，从而反推 `-3B0` 的语义。这属于"输入对照"，不是反推内部取值。

## 七、与先前结论的关系（修正）

1. 「σ=M/W 不在立柱函数里」——**错**。它在，只是走 `__vbaVarDiv`，x87 扫描看不到。
2. 「q_d 是外部算好的」——**对**。`-0x358`/`-0x320` 各只写一次，直接来自控件文本。
3. 「`-0x14C` 是长度量」——**对**（总长 v，出现在 `(v−a−L)·2+L)/v` 类算式中）。
4. 「`-0x3B0` 是外伸 a」——**部分对**，它在挠度族里确实当长度用，但在 `q_d·a·L²/8`
   里若当外伸，量纲不成立 ⇒ 需 §六 的验证。

## 九、输入对照实验（做过，未成立，如实记录）

想用「改输入 → 看输出怎么变」来定 `-0x3B0` / `-0x3F0` 的身份，不需要调试器。结果不成立。

### 9.1 先修了一个真 bug：剪贴板残留导致往「立柱跨度」里粘了中文

`V31A.SetField()` 的实现只有两步：

```
SendMessage(h, EM_SETSEL, 0, -1)   # 全选
SendMessage(h, WM_PASTE, 0, 0)     # 粘贴
```

**它只粘贴、不设置剪贴板**。我在 `col-sweep` 里直接调用它而没先写剪贴板，
于是把上一次操作残留在剪贴板里的中文（地区名/型材代号）粘进了立柱跨度输入框 →
V31 弹出「请输入正确数字」、预演不执行、所有输出为空。

**已修**（`v31_attach.ps1` 的 `col-sweep`）：

1. 每格写入前 `Clipboard.SetText("$值")`；
2. 写完 `Val()` 回读，与期望值逐字符比对，**不等就中止并打印实得内容**；
3. 每次「上一步」之后**重找窗体句柄**（窗体可能被重建）。

修后实测回读全部正确（`重进后 L='3000' a='0'` 等），屏幕上两个框是 `3000` / `700`，不再有中文。

### 9.2 但输出没变，实验不成立

四个用例（a = 0 / 700 / 1500 / 3000）输出**逐位相同**：

```
wk=2.146  W预选=29516.667  I预选=2134343.474  df=8.524  σ=74.366  τ=7.337
```

原因（已核实）：

- 立柱屏**没有「确认数据」按钮**，只有 `预演 / 上一步 / 下一步 / 退出` ——
  我先前按旧经验点「确认数据」是空点。
- 走 `上一步 → 下一步` 重建该屏后输入框值确实保留（`a` 的 0 / 1500 / 3000 都读到过），
  但 `预演` 输出仍是同一组数 ⇒ 要么这两格不是本屏计算实际读取的量，要么抓到的是另一个
  不随计算刷新的 RTF 面板（本次文本只有 630 字节）。

⇒ **这条替代路线没走通，不作为证据。** 要定 `-0x3B0` / `-0x3F0`，仍然只剩断点一条路：
在 `0x18BD970`（第一次 `__vbaVarDiv` 之前）下断，直接读 `[ebp-3B0h]`、`[ebp-3F0h]`、
`[ebp-2C8h]` 三个 double，与界面输入对照，一次定死。
