## 三、本轮新查明的两条规则

### 1）挠度限值有 20mm 绝对上限

`lim = min(L / 180, 20)`，上限常量即 V31 `dbl_4019E0 = 20`（双跨函数内引用 `0xD3CBB3` / `0xD3DE6F`）。

实测（单跨受拉）：

| L | L/180 | V31 lim |
|---|---|---|
| 3400 | 18.889 | 18.889 |
| 3500 | 19.444 | 19.444 |
| 3600 | **20.0** | 20（边界）|
| 3700 | 20.556 | **20** |
| 4500 | 25.0 | **20** |
| 5000 | 27.778 | **20** |

双跨同样受约束：Lc=4000（L1=6000/L2=2000）→ 20。
另外 `I_req` 用的是**截断后**的 lim（L=4000 时 5qkL⁴/(384E·20) = 3314285.714，V31 同值）。

### 2）L2 必须小于 L1/2，否则「无效输入」

- L2 = L1/2（等跨）→ V31 **自动改成 L2−1**（界面显示 1499，用户实机观察印证）
- L2 > L1/2 → 弹「无效输入」对话框，不计算

### 3）wk → qk 的十进制修正

L=4000 案暴露：V31 `slot[7] = 0.0012650000000000001`（比浮点 `1.265/1000` **大 1 ulp**），
于是 `qk 输入 = 1.3915000000000002 → 1.392`；复刻用 double 直算得 `1.3914999999999998 → 1.391`（错一档，
整条 σ/τ/df 全偏 0.048%）。

修法：`wk` 先用 decimal 舍回十进制（`Math.Round((decimal)wk3, 3)`），再按十进制 `/1000 × bay`。

### 踩坑

- **预演单次点击偶发不刷新** → 每组固定点两次（读到的是上一组残留值，曾导致两行数据"对调"的假象）
- `L2 ≥ L1/2` 会弹「无效输入」模态框 → 必须用 `kill_dialogs.py` 收掉，否则后续点击全部落到模态框上
- PowerShell 里 `Add-Type` 被安全策略拦（只能在 `-File` 运行的 .ps1 内用）；含中文的 .ps1 必须存 **UTF-8 带 BOM**
- python ctypes 在 64 位下必须声明 `GlobalAlloc/GlobalLock` 的 `restype = c_void_p`，否则句柄截断
- 点单选/按钮用 `PostMessage(BM_CLICK)`，`SendMessage` 在弹模态框时会阻塞死锁
